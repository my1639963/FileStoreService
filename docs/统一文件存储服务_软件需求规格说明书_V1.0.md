# 1. 项目概述

## 1.1 建设背景

农牧业大数据平台后续将持续建设和接入种植业、畜牧业、屠宰追溯、农产品质量安全、电子证照、GIS、乡村振兴等多个业务子系统。各业务系统将产生图片、视频、PDF、Office、电子证照、检测报告、数据交换文件、GIS 文件及其他业务附件。

为避免各子系统重复建设文件上传、下载、存储、权限、生命周期和审计能力，建设统一文件存储服务，作为平台级公共微服务，为各业务系统提供标准化文件存储能力。

本文档定位为平台级公共微服务的软件需求基线。后续详细设计、编码、测试和验收应以经评审确认的版本为准。

**合规声明**：本服务作为平台级公共微服务，其安全设计和实现应满足以下要求：

- GB/T 22239-2019《信息安全技术 网络安全等级保护基本要求》第三级要求；
- GB/T 39786-2021《信息安全技术 信息系统密码应用基本要求》第三级要求；
- 信息技术应用创新（信创）相关要求，优先选用国产化软硬件产品。

最终定级以平台整体定级结果为准。

## 1.2 软件定位

统一文件存储服务（File Storage Service，简称 FSS）定位为农牧业大数据平台统一的文件存储基础服务。

核心原则：统一文件存储能力，不统一业务文件管理。

文件服务负责文件存储、访问、元数据、生命周期、完整性和存储抽象；业务系统负责业务对象、业务关系和业务权限。

## 1.3 建设目标

平台总体目标是建立统一、安全、标准化、可审计的文件存储服务能力，为各业务系统提供统一的文件存储基础设施。

### 1.3.1 统一文件存储入口

1. 建立统一文件存储入口；
2. 屏蔽 MinIO、RustFS 等底层存储差异；
3. 业务系统仅依赖 FileId，不直接依赖 Bucket、ObjectKey 和具体存储 SDK。

### 1.3.2 统一文件能力

1. 支持普通文件、大文件、分片上传、断点续传和秒传；
2. 支持文件完整性校验（SM3/SHA-256 双轨）；
3. 支持应用级文件隔离；
4. 支持统一认证、审计和安全体系；
5. FSS 管理后台始终拥有独立的用户账户、角色和权限管理体系；第三方业务系统以应用身份调用 FSS，FSS 不感知第三方系统的用户身份；
6. 国密能力统一由平台国密服务 API 提供；
7. 满足信创环境部署要求。

### 1.3.3 统一存储管理

1. 支持国产化部署环境；
2. 支持 MinIO 与 RustFS 之间的存储迁移；
3. 支持信创对象存储替换。

## 1.4 建设范围

### 1.4.1 本期建设范围

1. 文件上传（普通上传、分片上传、断点续传、秒传）；
2. 文件下载（流式下载、Range 断点下载、大文件下载）；
3. 文件删除（逻辑删除、物理清理、剩余信息保护）；
4. 文件查询与元数据管理；
5. FileId 与 StorageKey 分离；
6. 完整性校验（SM3/SHA-256 双轨，国密能力通过平台国密服务 API 获取）；
7. Storage Provider 抽象（MinIO / RustFS / S3 兼容）；
8. 应用隔离；
9. 认证与权限：
   - 第三方应用认证：AppId/AppSecret 获取 Access Token；
   - FSS 管理后台认证：本地账户登录，可选 SSO 联合登录；
10. 等保三角色体系（系统管理员、审计管理员、安全管理员）；
11. 应用凭据管理（AppId/AppSecret 分配、轮换、禁用）；
12. 审计日志；
13. 大文件与 Multipart 上传；
14. Presigned URL 临时访问；
15. 高可用与故障处理；
16. 健康检查；
17. 一致性检查与自动清理；
18. 管理后台基础能力；
19. FSS 本地管理用户账户、角色、权限管理；
20. 平台 SSO 联合登录集成（可选，仅用于管理后台）；
21. 平台国密服务 API 集成；
22. 信创环境适配。

### 1.4.2 本期不包含

以下内容原则上不纳入本期文件服务范围：

- 业务系统自身的角色权限；
- 业务系统数据权限；
- 业务系统业务流程权限；
- 业务文件管理逻辑；
- 复杂网盘式目录管理；
- 文件版本管理；
- 跨应用文件共享；
- 第三方业务系统的用户身份管理；
- 第三方业务系统的用户登录、会话、令牌管理；
- 病毒扫描；
- 在线预览；
- 图片缩略图；
- 视频转码；
- OCR；
- 全文检索；
- 智能分类；
- SSO 平台自身的用户注册、统一登录页面、统一密码策略等由 SSO 平台负责；FSS 本地管理账户的注册、登录、密码策略由 FSS 自身负责；
- 密码算法实现、密钥明文管理、KMS 自建能力。

## 1.7 建设原则

### 1.7.1 统一存储抽象

业务层不得直接依赖 MinioClient 等具体 SDK。MinIO 与 RustFS 优先通过 S3 Compatible API 进行适配。

### 1.7.2 FileId 与 StorageKey 分离

业务系统只保存 FileId，不直接保存 Bucket、StorageKey、MinIO URL 或 RustFS URL。

### 1.7.3 无状态设计

文件服务应采用无状态设计，可多实例部署。业务系统通过 REST API 调用文件服务。

### 1.7.4 最小权限

应用、用户、服务账号仅授予完成职责所需的最小权限。

### 1.7.5 全程审计

文件上传、下载、删除、恢复等关键操作均必须产生审计记录。

### 1.7.6 国密能力通过平台国密服务 API 提供

FSS 不实现密码算法，不管理密钥明文。FSS 使用平台分配的 AppId/AppSecret 调用国密服务 API。

### 1.7.7 FSS 管理后台拥有独立账户与权限体系，SSO 作为可选联合登录

FSS 管理后台始终拥有独立的用户账户、角色和权限管理体系，用于 FSS 自身管理（系统管理员、审计管理员、安全管理员）。

- FSS 的用户账户仅用于管理后台登录，不参与第三方业务系统的文件操作；
- 第三方系统调用 FSS 属于应用级调用，使用 AppId/AppSecret 获取 Access Token，请求中不携带用户身份；
- 用户可以使用 FSS 本地账户登录管理后台，也可以使用平台 SSO 账户登录，首次登录时绑定或创建本地账户；
- 所有管理后台权限判断均基于 FSS 本地账户和角色，SSO 不参与权限管理；
- 即使没有 SSO，FSS 也能完全独立运行，不影响任何功能。

### 1.7.8 等保三员分立

FSS 必须实现系统管理员、审计管理员、安全管理员三类角色的职责分离。三类角色不得由同一人兼任。

### 1.7.9 信创优先

系统设计和实现应优先选用信创合规的国产化软硬件产品。在同等功能条件下，优先选择国产 CPU、国产操作系统、国产数据库、国产中间件和国产对象存储。

### 1.7.10 等保与密评合规

系统设计和实现必须满足等保三级和密评三级要求。密码应用安全性评估应在系统投入运行前完成。

## 2.4 系统边界

文件服务负责：

- 文件存储、访问、元数据、生命周期；
- 存储抽象、完整性校验、审计；
- FSS 管理用户账户、角色、权限管理；
- 等保三角色体系（系统管理员、审计管理员、安全管理员）；
- 第三方应用 AppId/AppSecret 分配与管理；
- SSO 联合登录集成（可选，仅用于管理后台）；
- 国密服务 API 调用；
- 信创环境适配。

文件服务不负责：

- 业务权限、业务目录、业务对象、业务审批、业务流程、业务数据、业务统计、GIS 业务逻辑；
- 第三方业务系统的用户身份管理；
- 第三方业务系统的用户登录、会话、令牌管理；
- 文件版本管理、跨应用文件共享；
- SSO 平台自身的用户注册、统一登录页面、统一密码策略；
- 密码算法实现与密钥明文管理。

# 3. 功能需求

## 3.1 核心文件模型

核心对象为 FileObject。

| 属性              | 说明                                                         |
| ----------------- | ------------------------------------------------------------ |
| FileId            | 文件唯一标识                                                 |
| ApplicationId     | 所属应用，由 AppId 映射得到                                  |
| OriginalName      | 原始文件名                                                   |
| Extension         | 文件扩展名                                                   |
| ContentType       | MIME 类型                                                    |
| Size              | 文件大小                                                     |
| Sha256            | SHA-256 哈希值                                               |
| Sm3               | SM3 哈希值                                                   |
| StorageProvider   | 存储提供者标识                                               |
| Bucket            | 存储桶                                                       |
| StorageKey        | 存储对象键                                                   |
| Status            | 文件状态                                                     |
| CreatedByAppId    | 创建文件的应用 AppId；第三方应用调用时必填                   |
| CreatedByUserId   | 创建文件的 FSS 管理用户 UserId；仅当管理后台用户直接上传时填写，第三方应用调用时为空 |
| CreatedAt         | 创建时间                                                     |
| UpdatedAt         | 更新时间                                                     |
| DeletedAt         | 删除时间                                                     |

**F-CM-001**：系统应定义 FileObject 作为核心文件模型，包含上述全部属性。

**F-CM-002**：FileId 与 StorageKey 必须分离。业务系统只保存 FileId，不直接保存 Bucket、StorageKey、MinIO URL 或 RustFS URL。

**F-CM-003**：`CreatedByAppId` 记录创建文件的应用 AppId，来自 Access Token 对应的应用身份，第三方应用调用时必须记录。

**F-CM-004**：`CreatedByUserId` 为可选字段，仅当管理后台用户通过本地登录或 SSO 联合登录直接上传文件时填写。第三方应用调用 FSS 时，请求中不携带用户身份，该字段为空。

**F-CM-005**：FSS 不要求第三方应用传递用户身份，不要求 `CreatedByUserId` 非空。

**F-CM-006**：FSS 不提供文件版本管理。若业务系统需要版本管理，由业务系统自行保存多个 FileId，并在业务侧建立版本关系。

状态定义：

```text
TEMP → UPLOADING → ACTIVE → DELETED → PURGED
                        │
                        └──→ ABANDONED（终态，由异常上传会话清理任务触发）
```

| 编号      | 功能           | 要求                                     |
| --------- | -------------- | ---------------------------------------- |
| F-LC-001  | 逻辑删除       | 业务删除采用逻辑删除                     |
| F-LC-002  | 物理清理       | 经过保留周期后由后台任务执行物理清理     |
| F-LC-003  | 自动清理       | 异常上传会话应支持自动清理               |
| F-LC-004  | 剩余信息保护   | 物理清理时须对存储空间进行安全擦除       |

要求：

- 业务删除采用逻辑删除，经过保留周期后由后台任务执行物理清理；
- 异常上传会话应支持自动清理；
- 物理清理时须执行剩余信息保护要求，对文件占用的存储空间进行覆写或擦除操作，确保原数据无法通过技术手段恢复；
- 数据库记录物理删除后，应对相应存储空间进行释放保护。

## 3.6 应用隔离与权限

| 编号      | 功能           | 要求                                     |
| --------- | -------------- | ---------------------------------------- |
| F-AI-001  | 应用隔离       | 文件必须绑定 ApplicationId               |
| F-AI-002  | 默认隔离       | 默认一个应用只能访问本应用文件           |
| F-AI-003  | 严格隔离       | 不支持跨应用文件共享，禁止跨应用访问     |

要求：

- 文件必须绑定 ApplicationId，ApplicationId 由 AppId 映射得到；
- 默认且唯一允许一个应用访问本应用文件；
- 文件服务不负责理解养殖场、企业、行政区划、牛羊、屠宰批次等业务概念；
- 业务系统负责业务权限判断，文件服务负责资源级访问控制；
- 文件操作权限基于应用身份和资源归属，不基于用户角色；
- 不支持跨应用文件共享。若业务确有跨应用使用文件需求，由业务系统在业务层处理；
- 后端必须执行 ApplicationId 与 FileId 的归属校验。

## 3.8 角色与职责（等保三员分立）

FSS 必须实现等保三级要求的角色分离。FSS 角色**仅用于 FSS 管理后台**，不用于第三方业务系统的文件操作。第三方系统调用 FSS 属于应用级调用，不映射为 FSS 用户角色。

| 角色         | 职责范围                                                         | 需求编号   |
| ------------ | ---------------------------------------------------------------- | ---------- |
| 系统管理员   | 系统资源配置、FSS 管理用户身份管理、系统加载和启动、异常处理、数据备份与恢复 | F-ROLE-001 |
| 审计管理员   | 审计日志查看、审计策略管理、审计分析、审计报告生成                 | F-ROLE-002 |
| 安全管理员   | 安全策略配置、权限分配、安全事件处置、应用凭据分配与轮换           | F-ROLE-003 |

要求：

- 系统管理员、审计管理员、安全管理员三类角色必须职责分离，不得由同一人兼任；
- 审计管理员只能查看和管理审计日志，不得参与系统运维和权限分配；
- 系统管理员不得查看或修改审计日志；
- 安全管理员负责权限策略、安全事件处置和应用凭据分配；
- 所有角色的操作均应记录审计日志；
- 角色权限遵循最小权限原则；
- 第三方业务系统的用户身份不属于 FSS 角色体系，FSS 不感知第三方系统的用户。

**F-ROLE-004**：第三方应用 AppId/AppSecret 由安全管理员分配，或由安全管理员授权系统管理员分配。

**F-ROLE-005**：AppId/AppSecret 通过线下安全方式传递给第三方应用对接方，不得通过在线申请流程自助获取。

**F-ROLE-006**：系统应支持 AppId/AppSecret 的轮换、禁用和过期管理。AppSecret 轮换后旧凭据应在合理缓冲期后失效。

**F-ROLE-007**：AppId/AppSecret 的分配、轮换、禁用操作必须记录审计日志。

| F-CR-004  | SM4 加密/解密  | 通过国密服务 API 进行 SM4 加密和解密     |

| F-CR-006  | 故障降级       | 国密服务不可用时，非密评场景可降级 SHA-256 并告警；密评场景禁止降级 |

要求：

- FSS 不实现密码算法、不生成、不存储、不导出密钥明文；
- 国密服务负责密钥全生命周期管理；
- FSS 调用国密服务 API 时使用 AppId/AppSecret 认证；
- 国密服务 API 调用应记录审计日志。

# 6. 接口规范

## 6.1 通用约定

HTTPS；JSON；UTF-8；ISO 8601；Authorization Bearer Token。所有 API 必须返回 TraceId。统一 API 前缀：`/api/fss/v1`

## 6.2 认证要求

FSS 支持以下认证方式：

### 6.2.1 应用认证（文件操作接口）

```http
Authorization: Bearer {access_token}
```

第三方应用使用 AppId + AppSecret 获取 Access Token。该认证方式不依赖 SSO，不携带用户身份。

### 6.2.2 管理后台认证（管理接口）

**本地登录（主）：**

```http
POST /api/fss/v1/auth/login
```

本地管理用户登录后获取 FSS 本地令牌。

**SSO 联合登录（可选）：**

配置 SSO 后，前端跳转 SSO 登录，回调后 FSS 校验 SSO 令牌，绑定或创建本地账户，并签发 FSS 本地令牌。后续请求使用 FSS 本地令牌。

### 6.2.3 国密服务调用认证

FSS 调用平台国密服务 API 时，使用平台分配的 AppId/AppSecret 获取国密服务访问令牌。

```http
X-App-Id: {fss_app_id}
X-App-Secret: {fss_app_secret}
```

## 6.3 请求与响应格式

统一响应包含 Code、Message、Data、TraceId/ErrorCode 等字段。

成功：

```json
{
  "code": 0,
  "message": "success",
  "data": {},
  "traceId": "trace-xxxx"
}
```

错误：

```json
{
  "code": 30001,
  "message": "File not found",
  "data": null,
  "traceId": "trace-xxxx",
  "errorCode": "FILE_NOT_FOUND"
}
```

不得向客户端暴露：StackTrace、数据库内部异常、MinIO/RustFS 内部信息、SSO 内部信息、国密服务内部信息、密钥明文、本地管理用户密码哈希和盐值。

## 6.4 文件操作接口

文件操作接口使用**应用认证**（AppId/AppSecret + Access Token），不需要 FSS 管理用户登录。

| 接口           | 方法   | 路径                              |
| -------------- | ------ | --------------------------------- |
| 上传文件       | POST   | `/api/fss/v1/files`               |
| 分片上传       | POST   | `/api/fss/v1/files/multipart`     |
| 完成分片       | POST   | `/api/fss/v1/files/{id}/complete` |
| 查询文件       | GET    | `/api/fss/v1/files/{id}`          |
| 下载文件       | GET    | `/api/fss/v1/files/{id}/download` |
| 获取临时 URL   | POST   | `/api/fss/v1/files/{id}/access-url` |
| 删除文件       | DELETE | `/api/fss/v1/files/{id}`          |
| 恢复文件       | POST   | `/api/fss/v1/files/{id}/restore`  |
| 文件 HEAD      | HEAD   | `/api/fss/v1/files/{id}`          |

## 6.5 管理接口

管理接口使用 **FSS 本地管理用户登录**，基于三角色进行权限判断。

| 接口           | 方法 | 路径                              | 权限要求       |
| -------------- | ---- | --------------------------------- | -------------- |

| 存储桶列表     | GET  | `/api/fss/v1/storage/buckets`     | 系统管理员     |
| 存储健康检查   | GET  | `/api/fss/v1/storage/health`      | 系统管理员     |
| 本地登录       | POST | `/api/fss/v1/auth/login`          | 无             |
| 本地登出       | POST | `/api/fss/v1/auth/logout`         | 已登录管理用户 |
| 当前用户信息   | GET  | `/api/fss/v1/auth/me`             | 已登录管理用户 |
| 本地用户列表   | GET  | `/api/fss/v1/users`               | 系统管理员     |
| 本地用户管理   | POST | `/api/fss/v1/users`               | 系统管理员     |
| 本地角色管理   | GET  | `/api/fss/v1/roles`               | 安全管理员     |
| 审计日志查询   | GET  | `/api/fss/v1/audit/logs`          | 审计管理员     |
| 应用凭据列表   | GET  | `/api/fss/v1/apps`                | 安全管理员     |

# 8. 安全需求

## 8.1 文件安全

必须：上传时至少进行文件大小、扩展名、MIME 类型及文件头检查；文件类型白名单服务器端强制执行；禁止目录穿越和危险文件名；文件完整性校验支持 SM3/SHA-256 双轨。

## 8.2 传输安全

支持 TLS 1.2 及以上，信创环境优先使用国密 SSL 协议或支持 SM2/SM3/SM4 的 TLS 实现；生产环境 API 使用 HTTPS；管理接口与业务接口隔离；对象存储通信采用安全连接；禁止明文传输敏感材料；与国密服务之间建议内网 HTTPS；与 SSO 平台之间建议内网 HTTPS，仅在使用 SSO 联合登录时需要。

## 8.3 身份认证安全

应用认证：
- AppId；
- AppSecret，即 security；
- Access Token；
- AppSecret 应加密存储，不得明文落盘；
- AppId/AppSecret 由安全管理员分配，线下传递。

管理后台认证：
- FSS 本地管理账户认证为主：密码使用 SM3 加盐摘要存储；支持登录失败锁定、验证码、会话超时；本地令牌使用国密服务 API 签名或完整性保护；
- SSO 联合登录为可选：FSS 校验 SSO 令牌，映射到本地管理账户，签发 FSS 本地令牌；SSO 不参与权限管理。

国密服务认证：FSS 使用平台分配的 AppId/AppSecret 调用国密服务 API；FSS 不接触国密密钥明文。

## 8.4 权限控制

采用 RBAC + 资源归属控制。

**管理后台权限检查顺序：**

```text
管理用户身份认证（FSS 本地令牌）
 ↓
FSS 本地角色检查（系统管理员 / 审计管理员 / 安全管理员）
 ↓
API 权限
```

**文件操作权限检查顺序：**

```text
应用身份认证（AppId/AppSecret + Access Token）
 ↓
ApplicationId 归属
 ↓
FileId 归属
 ↓
文件状态
```

说明：

- 文件操作不基于用户角色，基于应用身份和资源归属；
- 管理后台操作基于 FSS 本地管理用户角色；
- 第三方应用调用不映射为 FSS 用户角色。

## 8.5 应用隔离安全

必须实现：App A → 只能访问 App A 的文件。

禁止：App A 通过猜测 FileId、修改请求参数等方式访问 App B 的文件。

后端必须执行 ApplicationId 与 FileId 的归属校验。

FSS 不支持跨应用文件共享。若业务需要跨应用使用文件，由业务系统在业务层处理。

第三方应用调用 FSS 属于应用级调用，FSS 仅校验应用身份，不感知第三方系统的用户身份。

## 8.6 Token 安全

Token 必须：签名（优先通过国密服务 API 使用 SM2 或 HMAC-SM3）、设置有效期、防止重放、支持撤销、不得写入普通业务日志、存储于缓存时应加密存储并设置合理过期时间。

FSS 本地管理令牌由 FSS 负责签发和生命周期管理，必须通过国密服务 API 进行签名或完整性保护，支持撤销和过期。SSO 联合登录成功后，FSS 仍签发本地令牌。

应用 Access Token 由 FSS 使用 AppId/AppSecret 认证后签发。

## 8.7 API 安全

API 必须支持：参数校验、Body 大小限制、字段长度限制、限流、配额、防重放、请求签名、幂等、CORS 控制、Security Headers。

## 8.8 审计安全

审计日志：追加写入、不允许普通业务接口修改、不允许普通管理员删除、使用国密服务 API 的 SM3 摘要或 SM2 签名保证完整性、支持独立归档、支持定期备份、保存时间不少于六个月。

审计管理员只能查看和管理审计日志，不得参与系统运维和权限分配。

## 8.9 日志安全

日志禁止包含：AppSecret、AccessToken、SSO 用户令牌明文、FSS 本地用户令牌明文、本地管理用户密码明文/密码哈希/盐值、SecretKey、国密服务密钥明文、临时访问 URL、明文业务数据。

## 8.10 对象存储安全

对象存储：独立网络、访问认证、健康检查、故障告警、权限隔离、操作审计。

## 8.11 国密集成与密码技术应用

文件服务自身不实现密码算法。国密能力通过平台国密服务 API 提供。

| 密码技术 | 应用场景 | 要求 |
| -------- | -------- | ---- |
| SM3 | 文件完整性校验 | 通过国密服务 API 计算，密评场景优先使用 |
| SM3 | 审计日志完整性 | 通过国密服务 API 生成摘要 |
| SM3 | 本地管理用户口令摘要 | 本地管理用户密码使用 SM3 加盐摘要 |
| SM3 | 应用凭据摘要 | AppSecret 使用 SM3 摘要存储 |
| SM2 | 身份认证 | Token 签名、请求签名可通过国密服务 API 使用 SM2 |
| SM2 | 审计日志签名 | 可通过国密服务 API 对审计日志签名 |
| SM4 | 文件加密存储 | 通过国密服务 API 实现 |
| SM4 | 存储配置加密 | AccessKey/SecretKey 等敏感配置通过国密服务 API 加密存储 |

## 8.12 密钥管理

密钥全生命周期管理由平台国密服务负责。FSS 不硬编码密钥、不持久化密钥明文、不在日志中输出密钥、使用 AppId/AppSecret 安全调用国密服务。

# 12. 典型业务流程

## 12.1 第三方应用接入（应用级调用）

```text
第三方应用对接方
 ↓
向安全管理员提出接入申请
 ↓
安全管理员审核
 ↓
安全管理员在 FSS 管理后台创建应用凭据
 ↓
系统生成 AppId 和 AppSecret
 ↓
安全管理员通过线下安全方式将 AppId/AppSecret 传递给对接方
 ↓
对接方使用 AppId/AppSecret 获取 Access Token
 ↓
对接方使用 Access Token 调用 FSS API
 ↓
FSS 记录 PrincipalType = APP，PrincipalId = AppId
 ↓
FSS 校验应用身份与 ApplicationId
 ↓
文件类型白名单/大小检查/文件头校验
 ↓
调用平台国密服务 API 计算 SM3
 ↓
秒传判断（SM3/SHA-256 + Size 匹配）
 ↓
Storage Provider
 ↓
MinIO / RustFS（可选 SM4 加密存储）
 ↓
返回 FileId、文件名、大小和 SHA-256/SM3
 ↓
业务表只保存 FileId
```

第三方应用调用 FSS 时，请求中不携带用户身份，FSS 不获取 UserId。

## 12.2 FSS 管理后台本地登录

```text
FSS 管理员
 ↓
FSS 管理后台本地登录（用户名+密码，密码 SM3 加盐摘要校验）
 ↓
FSS 签发本地管理令牌
 ↓
管理员携带本地管理令牌访问管理后台
 ↓
FSS 校验本地管理令牌并根据角色判断权限
 ↓
管理操作记录审计，PrincipalType = USER，PrincipalId = FSS 本地 UserId
```

## 12.3 FSS 管理后台 SSO 联合登录（可选）

```text
FSS 管理员
 ↓
选择使用 SSO 登录
 ↓
跳转平台 SSO 认证
 ↓
SSO 认证成功后回调 FSS
 ↓
FSS 校验 SSO 令牌，获取外部身份标识
 ↓
查找或创建 FSS 本地管理账户
 ↓
FSS 签发本地管理令牌
 ↓
后续请求使用 FSS 本地管理令牌
 ↓
权限判断基于 FSS 本地角色
```
