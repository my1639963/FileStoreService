# 1. 项目概述

## 1.1 建设背景

农牧业大数据平台后续将持续建设和接入种植业、畜牧业、屠宰追溯、农产品质量安全、电子证照、GIS、乡村振兴等多个业务子系统。各业务系统将产生图片、视频、PDF、Office、电子证照、检测报告、数据交换文件、GIS 文件及其他业务附件。

为避免各子系统重复建设文件上传、下载、存储、权限、生命周期和审计能力，建设统一文件存储服务，作为平台级公共微服务，为各业务系统提供标准化文件存储能力。

本文档定位为平台级公共微服务的软件需求基线。后续详细设计、编码、测试和验收应以经评审确认的版本为准。

**合规声明**：本服务作为平台级公共微服务，其安全设计和实现应满足以下要求：

- GB/T 22239-2019《信息安全技术 网络安全等级保护基本要求》第三级要求；
- GB/T 39786-2021《信息安全技术 信息系统密码应用基本要求》第三级要求；
- 信息技术应用创新（信创）相关要求。

**责任边界声明**：FSS 按平台整体密码应用方案和等保方案进行能力集成，FSS 自身承担的需求由 FSS 实现；平台国密服务承担密码运算和密钥管理；对象存储承担物理介质层数据保护；最终密评对象、测评范围和符合性以平台整体方案及正式测评结果为准。

最终定级以平台整体定级结果为准。

## 1.2 软件定位

统一文件存储服务（File Storage Service，简称 FSS）定位为农牧业大数据平台统一的文件存储基础服务。

核心原则：统一文件存储能力，不统一业务文件管理。

文件服务负责文件存储、访问、元数据、生命周期、完整性和存储抽象；业务系统负责业务对象、业务关系和业务权限。

## 1.3 建设目标

平台总体目标是建立统一、安全、标准化、可审计的文件存储服务能力，为各业务系统提供统一的文件存储基础设施。

### 1.3.1 统一文件存储入口

1. 建立统一文件存储入口；
2. 屏蔽 MinIO、RustFS 等底层存储差异；
3. 业务系统仅依赖 FileId，不直接依赖 Bucket、ObjectKey 和具体存储 SDK。

### 1.3.2 统一文件能力

1. 支持普通文件、大文件、分片上传、断点续传和秒传；
2. 支持文件完整性校验（SM3/SHA-256 双轨）；
3. 支持应用级文件隔离；
4. 支持统一认证、审计和安全体系；
5. FSS 管理后台始终拥有独立的用户账户、角色和权限管理体系；第三方业务系统以应用身份调用 FSS，FSS 不感知第三方系统的用户身份；
6. 国密能力统一由平台国密服务 API 提供；
7. 满足信创环境部署要求。

### 1.3.3 统一存储管理

1. 支持国产化部署环境；
2. 支持 MinIO 与 RustFS 之间的存储迁移；
3. 支持信创对象存储替换。

## 1.4 建设范围

### 1.4.1 本期建设范围

1. 文件上传（普通上传、分片上传、断点续传、秒传）；
2. 文件下载（流式下载、Range 断点下载、大文件下载）；
3. 文件删除（逻辑删除、物理清理、物理对象引用计数）；
4. 文件查询与元数据管理；
5. FileId 与 StorageKey 分离；
6. StorageObject 物理对象模型与引用计数；
7. 完整性校验（SM3/SHA-256 双轨，国密能力通过平台国密服务 API 获取，支持流式 SM3）；
8. Storage Provider 抽象（MinIO / RustFS / S3 兼容）；
9. 应用隔离与应用 Scope；
10. 认证与权限：
    - 第三方应用认证：AppId/AppSecret + Access Token + Scope；
    - FSS 管理后台认证：本地账户登录，可选 SSO 联合登录；
    - 管理令牌与应用令牌分离；
11. 等保三角色体系（系统管理员、审计管理员、安全管理员）及互斥强制约束；
12. 应用凭据管理（AppId/AppSecret 分配、轮换、禁用、缓冲期）；
13. 审计日志（完整性链）；
14. 大文件与 Multipart 上传（UploadSession 模型）；
15. 临时访问 URL 双模式（FSS 代理 + 原生 Presigned）；
16. 高可用与故障处理；
17. 健康检查（合成对象方案）；
18. 一致性检查与孤儿对象人工确认清理；
19. 后台任务调度、分布式锁、执行窗口与失败重试；
20. 限流与配额（多维度）；
21. 管理后台基础能力；
22. FSS 本地管理用户账户、角色、权限管理；
23. 平台 SSO 联合登录集成（可选，仅用于管理后台）；
24. 平台国密服务 API 集成；
25. 数据分区、归档与膨胀治理；
26. 灾备（RPO/RTO）；
27. 信创环境适配。

### 1.4.2 本期不包含

- 业务系统自身的角色权限、数据权限、业务流程权限；
- 业务文件管理逻辑；
- 复杂网盘式目录管理；
- 文件版本管理；
- 跨应用文件共享；
- 第三方业务系统的用户身份管理、用户登录、会话、令牌管理；
- 病毒扫描、在线预览、图片缩略图、视频转码、OCR、全文检索、智能分类；
- SSO 平台自身的用户注册、统一登录页面、统一密码策略；
- 密码算法实现、密钥明文持久化、KMS 自建能力；
- 底层物理介质安全擦除的具体实现（由对象存储与基础设施承担）。

## 1.7 建设原则

### 1.7.1 统一存储抽象

业务层不得直接依赖 MinioClient 等具体 SDK。

### 1.7.2 FileId 与 StorageKey 分离

业务系统只保存 FileId，不直接保存 Bucket、StorageKey、MinIO URL 或 RustFS URL。

### 1.7.3 逻辑对象与物理对象分离

FileObject 承载逻辑元数据和应用隔离；StorageObject 承载物理对象和引用计数。物理对象生命周期由引用计数决定。

### 1.7.4 无状态设计

文件服务应采用无状态设计，可多实例部署。

### 1.7.5 最小权限

应用、用户、服务账号仅授予完成职责所需的最小权限。应用访问受 ApplicationScope 约束。

### 1.7.6 全程审计

文件上传、下载、删除、恢复等关键操作均必须产生审计记录，审计日志通过完整性链防篡改。

### 1.7.7 国密能力通过平台国密服务 API 提供

FSS 不实现密码算法。FSS 使用平台分配的 AppId/AppSecret 调用国密服务 API。大文件 SM3 采用流式摘要能力。

### 1.7.8 FSS 管理后台拥有独立账户与权限体系，SSO 作为可选联合登录

FSS 管理后台始终拥有独立的用户账户、角色和权限管理体系。第三方系统调用 FSS 属于应用级调用，FSS 不感知第三方系统的用户身份。

### 1.7.9 等保三员分立与互斥

FSS 必须实现系统管理员、审计管理员、安全管理员三类角色的职责分离。互斥约束由应用层事务强制实施，数据库层提供辅助约束。

### 1.7.10 信创优先

在同等功能条件下，优先选择国产 CPU、国产操作系统、国产数据库、国产中间件和国产对象存储。信创组件选型应通过项目兼容性测试验证。

### 1.7.11 等保与密评合规

系统设计和实现必须满足等保三级和密评三级要求。密码应用安全性评估应在系统投入运行前完成。

### 1.7.12 多实例安全并发

后台任务、清理、一致性检查等作业必须通过分布式锁保证多实例下不重复执行。

### 1.7.13 责任边界清晰

FSS、平台国密服务、对象存储、数据库、SSO 各自承担明确的责任。详见第 13 章责任边界矩阵。

| 健康检查模块     | 合成对象健康检查、认证健康检查            |
| 后台任务模块     | 调度、分布式锁、执行窗口、失败重试、告警  |
| 限流与配额模块   | 应用级/全局 QPS、并发、带宽、容量、文件数 |
| 管理控制台       | 基础管理能力                              |
| 身份认证模块     | 管理后台本地账户认证、SSO 联合登录        |
| 角色与权限模块   | 三员角色与互斥强制约束、权限矩阵          |
| 应用凭据管理模块 | AppId/AppSecret 分配、轮换、Scope 管理    |
| 国密服务集成模块 | AppId/AppSecret 调用国密服务 API，含流式 SM3 |

## 2.4 系统边界

文件服务负责：

- 逻辑文件元数据、应用隔离、逻辑状态机；
- 物理对象引用计数、物理生命周期；
- 存储抽象、完整性校验、审计完整性链；
- FSS 管理用户账户、角色、权限管理；
- 三员角色互斥应用层约束；
- 第三方应用 AppId/AppSecret 分配与 Scope 管理；
- SSO 联合登录集成（可选，仅管理后台）；
- 国密服务 API 调用（含流式 SM3 会话）；
- 限流、配额、后台任务调度；
- 数据分区与归档；
- 信创环境适配。

文件服务不负责：

- 业务权限、业务目录、业务对象、业务审批、业务流程、业务数据、业务统计、GIS 业务逻辑；
- 第三方业务系统的用户身份管理；
- 文件版本管理、跨应用文件共享；
- SSO 平台自身的用户注册、统一登录页面、统一密码策略；
- 密码算法实现与密钥明文持久化；
- 对象存储底层物理介质安全擦除；
- 对象存储原生 Presigned URL 的签名协议实现。

### 3.1.2 StorageObject（物理对象）

| 属性              | 说明                                                         |
| ----------------- | ------------------------------------------------------------ |
| StorageObjectId   | 物理对象唯一标识                                             |
| StorageProviderId | 存储提供者                                                   |
| Bucket            | 存储桶                                                       |
| StorageKey        | 物理对象键                                                   |
| Size              | 物理对象大小                                                 |
| Sha256            | SHA-256 哈希值                                               |
| Sm3               | SM3 哈希值                                                   |
| ReferenceCount    | 引用计数                                                     |
| Status            | 物理状态（ACTIVE / PENDING_DELETE / PURGED）                 |
| EncryptionKeyId   | 若启用 SM4 加密，记录密钥引用                                |
| CreatedAt         | 创建时间                                                     |
| UpdatedAt         | 更新时间                                                     |

**F-CM-001**：系统应定义 FileObject 和 StorageObject 两个核心模型。

**F-CM-002**：FileId 与 StorageKey 必须通过 StorageObject 间接关联，FileObject 不直接持有 StorageKey。

**F-CM-003**：秒传命中已有物理对象时，创建新的 FileObject 和 StorageObject 引用关系（或复用 StorageObject 并增加 ReferenceCount），不复制物理对象。

**F-CM-004**：StorageObject 的 ReferenceCount 由 FileObject 的创建、删除驱动。

**F-CM-005**：ReferenceCount 为 0 时，StorageObject 进入 PENDING_DELETE 状态，由后台任务延迟物理清理。

**F-CM-006**：FSS 不提供文件版本管理。若业务系统需要版本管理，由业务系统自行保存多个 FileId。

**F-CM-007**：`ApplicationId` 为 FSS 数据库内应用标识，与对外 `AppId` 通过映射表关联。

**F-CM-008**：秒传可进行跨 ApplicationId 的物理对象去重，但不得产生跨应用 FileId、API 访问权限或元数据可见性。

| F-UP-007  | 文件头校验     | 通过二进制文件头检测验证文件真实类型     |
| F-UP-008  | 文件名安全     | 过滤或转义危险文件名，防止目录穿越       |
| F-UP-009  | 文件大小限制   | 单文件上传大小不超过应用配置上限         |

| 编号      | 功能               | 要求                                     |
| --------- | ------------------ | ---------------------------------------- |
| F-DL-001  | 流式下载           | 支持文件流式下载                         |
| F-DL-002  | Range 下载         | 支持 Range 断点下载                      |
| F-DL-003  | 大文件下载         | 支持大文件下载                           |
| F-DL-004  | FSS Access URL     | 支持 FSS 自有临时访问 URL                |
| F-DL-005  | S3 Presigned URL   | 支持生成对象存储原生 Presigned URL       |
| F-DL-006  | FSS Access URL 撤销 | 支持主动撤销 FSS 临时访问 URL            |
| F-DL-007  | FSS Access URL 绑定 | FSS 临时访问 URL 必须绑定 FileId 和 ApplicationId |
| F-DL-008  | FSS Access URL 有效期 | 最大有效期不得超过 1 小时              |
| F-DL-009  | FSS Access URL IP 绑定 | 支持可选绑定客户端 IP                  |
| F-DL-010  | S3 Presigned URL 签名 | 遵循具体 Storage Provider 的签名协议 |

要求：

**FSS Access URL（模式 A）：**

```text
Client → FSS /access-url → FSS 校验 Token → FSS 校验 FileId/ApplicationId → FSS 代理下载
```

- FSS Access URL 的完整性保护可使用平台国密服务提供的 SM2/SM3；
- FSS Access URL 支持主动撤销；
- FSS Access URL 必须绑定 FileId 和 ApplicationId；
- FSS Access URL 最大有效期不超过 1 小时；
- FSS Access URL 支持可选绑定客户端 IP。

**S3 Presigned URL（模式 B）：**

```text
Client → FSS → 生成 S3 Presigned URL → Client → MinIO/RustFS
```

- S3 Presigned URL 必须遵循对应 Storage Provider 的协议和签名机制；
- 不得要求 MinIO/RustFS 直接识别非其协议规定的国密签名格式；
- FSS 应记录生成 S3 Presigned URL 的审计日志，但不得输出 URL 明文。

## 3.6 文件生命周期

### 3.6.1 FileObject 逻辑状态

```text
TEMP → UPLOADING → ACTIVE → DELETED → PURGED
                        │
                        └──→ ABANDONED（终态）
```

合法流转：

| 起始状态   | 允许的目标状态        | 触发条件                     |
| ---------- | --------------------- | ---------------------------- |
| TEMP       | UPLOADING、ABANDONED  | 开始上传 / 超时              |
| UPLOADING  | ACTIVE、ABANDONED     | 上传完成 / 超时或失败        |
| ACTIVE     | DELETED               | 业务删除                     |
| DELETED    | ACTIVE、PURGED        | 恢复 / 保留期到期            |
| PURGED     | 无                    | 终态                         |
| ABANDONED  | 无                    | 终态                         |

### 3.6.2 StorageObject 物理状态

```text
ACTIVE → PENDING_DELETE → PURGED
```

| 起始状态       | 允许的目标状态   | 触发条件                         |
| -------------- | ---------------- | -------------------------------- |
| ACTIVE         | PENDING_DELETE   | ReferenceCount 降为 0            |
| PENDING_DELETE | ACTIVE           | 新引用产生（秒传命中）           |
| PENDING_DELETE | PURGED           | 延迟窗口到期后物理清理           |
| PURGED         | 无               | 终态                             |

| 编号      | 功能           | 要求                                     |
| --------- | -------------- | ---------------------------------------- |
| F-LC-001  | 逻辑删除       | 业务删除采用逻辑删除，FileObject 进入 DELETED |
| F-LC-002  | 引用计数       | FileObject 删除时 StorageObject 引用计数递减 |
| F-LC-003  | 物理清理       | StorageObject 引用计数为 0 且延迟窗口到期后物理清理 |
| F-LC-004  | 自动清理       | 异常 UploadSession 支持自动清理          |
| F-LC-005  | 状态机强制     | 接口层必须拒绝非法状态流转               |
| F-LC-006  | 不可恢复       | PURGED 和 ABANDONED 状态文件不可恢复     |
| F-LC-007  | 物理对象保护   | 有引用的 StorageObject 不得被删除        |

要求：

- FileObject 逻辑删除后，StorageObject 引用计数递减；
- 引用计数为 0 时，StorageObject 进入 PENDING_DELETE；
- PENDING_DELETE 期间若新引用产生，可回到 ACTIVE；
- 延迟窗口到期后执行物理清理；
- 物理清理通过 Storage Provider 执行对象删除，并记录删除结果。

## 3.7 剩余信息保护

| 编号      | 功能           | 要求                                     |
| --------- | -------------- | ---------------------------------------- |
| F-RI-001  | 对象删除       | FSS 通过 Storage Provider 执行对象删除，记录删除结果 |
| F-RI-002  | 内存清理       | 敏感数据使用后应及时清零内存             |
| F-RI-003  | 数据库空间保护 | 数据库记录删除后应确保残留数据不可恢复   |
| F-RI-004  | 责任分层       | FSS 负责对象删除及审计；底层物理介质擦除由对象存储和基础设施承担 |
| F-RI-005  | 凭据生命周期   | 运行时解密凭据在最小生命周期内使用后清除 |

要求：

- FSS 负责通过 Storage Provider 执行对象删除，并确保删除操作结果可审计；
- 底层介质剩余信息保护由对象存储系统及底层存储基础设施按介质特性实施；
- FSS 不对无法由应用层直接控制的底层物理介质擦除作出实现承诺；
- 数据库层面应通过数据库自身机制或应用层逻辑确保删除记录后的空间保护；
- 本地账户模式下，用户密码哈希、盐值、令牌签名材料等敏感数据不得明文存储。

| 角色         | 职责范围                                                         | 需求编号   |
| ------------ | ---------------------------------------------------------------- | ---------- |
| 系统管理员   | 系统资源配置、FSS 管理用户身份管理、系统加载和启动、异常处理、数据备份与恢复 | F-ROLE-001 |
| 审计管理员   | 审计日志查看、审计策略管理、审计分析、审计报告生成                 | F-ROLE-002 |
| 安全管理员   | 安全策略配置、权限分配、安全事件处置、应用凭据分配与轮换           | F-ROLE-003 |

**F-ROLE-004**：AppId/AppSecret 由安全管理员分配，或由安全管理员授权系统管理员分配。

**F-ROLE-005**：AppId/AppSecret 通过线下安全方式传递，不得通过在线申请流程自助获取。

- 校验实现方式：应用层通过数据库事务对目标用户加锁，查询现有三员角色，若存在冲突则拒绝写入；
- 数据库层提供 `UNIQUE(UserId, RoleId)` 约束作为基础保障；
- 对于项目指定的主数据库，可在适配层补充 CHECK 约束或触发器作为最终兜底；
- 数据库特定实现不得作为跨数据库统一需求。

**F-ROLE-009（缓冲期配置）**：AppSecret 轮换缓冲期支持按应用配置，全局可配置最大上限（建议不超过 24 小时）。缓冲期不得超过上限。

**F-ROLE-010（权限矩阵）**：管理后台应定义角色-权限-API 矩阵，包括用户管理、角色管理、应用管理、配额管理、存储管理、审计查询、系统配置等权限。

**F-ROLE-011（账号生命周期）**：支持账号创建、启用、禁用、锁定、删除、离岗，离岗用户必须及时回收权限。

## 3.16 应用 Access Token 模型

## 3.17 应用凭据管理

**F-AC-001**：AppSecret 必须为高强度随机凭据，不得由用户自定义。

**F-AC-002**：AppSecretHash 使用 SM3 摘要存储，不保存明文。

**F-AC-003**：AppSecret 支持轮换，轮换期间旧 Secret 进入 Grace Period：

```text
新 Secret 生效
 ↓
旧 Secret 在 Grace Period 内继续有效
 ↓
Grace Period 到期
 ↓
旧 Secret 立即失效
```

**F-AC-004**：RotationBufferHours 支持按应用配置，全局设置上限（建议不超过 24 小时）。

**F-AC-005**：AppSecret 明文仅在分配时一次性输出给安全管理员线下传递。

**F-AC-006**：应用应支持 Scope 配置，默认不授予全部 Scope。

# 6. 接口规范

## 6.1 通用约定

HTTPS；JSON；UTF-8；ISO 8601；Authorization Bearer Token。所有 API 必须返回 TraceId。统一 API 前缀：`/api/fss/v1`

## 6.2 认证要求

### 6.2.1 应用认证（文件操作接口）

```http
Authorization: Bearer {access_token}
X-Request-Scope: {scope}
```

应用使用 AppId + AppSecret 获取 Access Token。请求必须校验 Scope。

### 6.2.2 管理后台认证（管理接口）

```http
Authorization: Bearer {management_token}
```

### 6.2.3 国密服务调用认证

```http
X-App-Id: {fss_app_id}
X-App-Secret: {fss_app_secret}
```

## 6.3 请求与响应格式

统一响应包含 Code、Message、Data、TraceId/ErrorCode 等字段。

不得向客户端暴露：StackTrace、数据库内部异常、MinIO/RustFS 内部信息、SSO 内部信息、国密服务内部信息、密钥明文、本地管理用户密码哈希和盐值。

# 8. 安全需求

## 8.1 文件安全

上传时至少进行文件大小、扩展名、MIME 类型及文件头检查；文件类型白名单服务器端强制执行；禁止目录穿越和危险文件名；文件完整性校验支持 SM3/SHA-256 双轨；大文件 SM3 通过流式会话完成。

## 8.2 传输安全

支持 TLS 1.2 及以上，信创环境优先使用国密 SSL 协议或支持 SM2/SM3/SM4 的 TLS 实现；生产环境 API 使用 HTTPS；管理接口与业务接口隔离；对象存储通信采用安全连接。

## 8.3 身份认证安全

应用认证：AppId、AppSecret、Access Token、Scope。AppSecret 高强度随机、加密存储、线下传递。

管理后台认证：FSS 本地管理账户认证为主；密码 SM3 加盐摘要 + 服务端迭代策略；支持登录失败锁定、验证码、会话超时、密码复杂度、历史密码、密码有效期、首次登录强制改密。

国密服务认证：FSS 使用平台分配的 AppId/AppSecret 调用国密服务 API。

## 8.4 权限控制

**管理后台权限检查顺序：**

```text
管理用户身份认证（ManagementToken）
 ↓
FSS 本地角色检查（系统管理员 / 审计管理员 / 安全管理员）
 ↓
权限矩阵校验
 ↓
API 权限
```

**文件操作权限检查顺序：**

```text
应用身份认证（Access Token）
 ↓
Scope 校验
 ↓
限流与配额检查
 ↓
ApplicationId 归属
 ↓
FileId 归属
 ↓
文件状态
```

## 8.5 应用隔离安全

必须实现：App A → 只能访问 App A 的文件。

后端必须执行 ApplicationId 与 FileId 的归属校验。

FSS 不支持跨应用文件共享。

## 8.6 Token 安全

Token 必须签名、设置有效期、防止重放、支持撤销、不得写入普通业务日志、存储于缓存时应加密。

ManagementToken 与 ApplicationAccessToken 分离。

## 8.7 API 安全

API 必须支持：参数校验、Body 大小限制、字段长度限制、限流、配额、防重放、请求签名、幂等、CORS 控制、Security Headers。

## 8.8 审计安全

审计日志：追加写入、不允许业务接口修改、审计管理员仅有查询导出权限、使用完整性链和定期 SM2 签名、独立归档、定期备份、保存时间不少于六个月、时间戳来自统一可信时间源。

## 8.9 日志安全

日志禁止包含：AppSecret、AccessToken、ManagementToken、SSO 用户令牌明文、本地管理用户密码明文/密码哈希/盐值、SecretKey、国密服务密钥明文、临时访问 URL 明文、明文业务数据。

## 8.10 对象存储安全

对象存储：独立网络、访问认证、健康检查、故障告警、权限隔离、操作审计。

## 8.11 国密集成与密码技术应用

| 密码技术 | 应用场景 | 要求 |
| -------- | -------- | ---- |
| SM3 | 文件完整性校验 | 通过国密服务 API 计算，大文件使用流式会话 |
| SM3 | 审计完整性链 | 通过国密服务 API 生成链式摘要 |
| SM3 | 本地管理用户口令摘要 | 使用 SM3 加盐摘要 + 服务端迭代策略 |
| SM3 | 应用凭据摘要 | AppSecret 使用 SM3 摘要存储 |
| SM2 | 身份认证 | Token 签名、请求签名 |
| SM2 | 审计链签名 | 定期对审计链头签名 |
| SM4 | 文件加密存储 | 通过国密服务 API 实现 |
| SM4 | 存储配置加密 | AccessKey/SecretKey 加密存储 |

## 8.12 密钥管理

密钥全生命周期管理由平台国密服务负责。

FSS 侧要求：

- 不硬编码密钥；
- 不持久化密钥明文；
- 运行时解密凭据仅在建立连接所需最小生命周期内使用，使用后清除；
- 不在日志中输出密钥；
- SM4 加密密钥通过 keyId 引用。

## 8.13 密码应用方案衔接

FSS 的密码应用需求应与平台整体密码应用方案衔接，包括：密码应用边界、密码保护对象、密码算法、密码服务、密钥引用关系、密钥生命周期责任边界、密码服务故障策略、密码服务审计、密码产品/服务合规性。

最终密评对象、测评范围和符合性以平台整体密码应用方案及正式测评结果为准。

# 12. 典型业务流程

## 12.1 第三方应用普通上传

```text
第三方应用对接方
 ↓
向安全管理员提出接入申请
 ↓
安全管理员审核并分配 AppId/AppSecret 及 Scope
 ↓
线下安全传递 AppId/AppSecret
 ↓
应用使用 AppId/AppSecret 获取 Access Token
 ↓
应用使用 Access Token 调用 FSS API
 ↓
FSS 校验 Token、Scope
 ↓
FSS 执行限流与配额检查
 ↓
FSS 记录 PrincipalType = APP，PrincipalId = AppId
 ↓
上传文件
 ↓
调用国密服务流式 SM3 计算摘要
 ↓
创建 StorageObject
 ↓
创建 FileObject
 ↓
返回 FileId
```

## 12.2 秒传

```text
应用请求秒传检查
 ↓
FSS 根据 SHA-256/SM3 + Size 查询已有 StorageObject
 ↓
命中：
 ↓
创建新 FileObject
 ↓
关联已有 StorageObject
 ↓
StorageObject.ReferenceCount +1
 ↓
返回 FileId
 ↓
未命中：走普通上传流程
```

## 12.3 文件删除与物理对象生命周期

```text
应用请求删除 FileObject
 ↓
FileObject.Status = DELETED
 ↓
StorageObject.ReferenceCount -1
 ↓
若 ReferenceCount > 0：
    StorageObject 保持 ACTIVE
 ↓
若 ReferenceCount == 0：
    StorageObject.Status = PENDING_DELETE
 ↓
延迟窗口到期
 ↓
后台任务通过 Storage Provider 删除物理对象
 ↓
StorageObject.Status = PURGED
 ↓
记录审计
```

## 12.4 FSS Access URL

```text
应用请求生成 FSS Access URL
 ↓
FSS 校验 Token、Scope、FileId 归属
 ↓
生成 AccessUrlToken，绑定 FileId/ApplicationId/ExpiresAt
 ↓
调用国密服务使用 SM2/SM3 签名
 ↓
返回 FSS Access URL
 ↓
Client 携带 URL 请求 FSS
 ↓
FSS 校验 Token、签名、有效性、IP 绑定
 ↓
FSS 代理下载对象
```

## 12.5 S3 Presigned URL

```text
应用请求生成 S3 Presigned URL
 ↓
FSS 校验 Token、Scope、FileId 归属
 ↓
FSS 使用 Storage Provider 凭据生成 S3 Presigned URL
 ↓
返回 URL（遵循对象存储协议签名机制）
 ↓
Client 直接访问对象存储
 ↓
记录审计
```

## 12.6 后台任务执行

```text
调度触发
 ↓
尝试获取分布式锁
 ↓
获取失败：跳过
 ↓
获取成功：检查执行窗口
 ↓
执行任务，记录 JobId/ExecutionId/NodeId/LockId/进度
 ↓
失败按策略有限重试
 ↓
连续失败触发告警
 ↓
释放锁
```

## 12.7 一致性检查四象限处理

```text
一致性检查任务执行
 ↓
扫描 FileObject / StorageObject / 物理对象
 ↓
DB 有 / Object 有：正常
 ↓
DB 有 / Object 无：丢失对象，告警 + 标记 + 人工处置
 ↓
DB 无 / Object 有：孤儿对象，标记 + 等待管理员确认
 ↓
DB 无 / Object 无：正常
 ↓
记录一致性检查结果
```

## 12.8 FSS 管理后台 SSO 联合登录

```text
FSS 管理员
 ↓
选择使用 SSO 登录
 ↓
跳转平台 SSO 认证
 ↓
SSO 认证成功后回调 FSS
 ↓
FSS 校验 SSO 令牌，获取外部身份标识
 ↓
查找或创建 FSS 本地管理账户（默认无三员角色）
 ↓
FSS 签发 ManagementToken
 ↓
安全管理员按需分配角色
```
